# Timetable preparation util

This application is used as a helper in constructing a time table for university courses.

1. The application should be written in Javascript, for client-side only usage, able to run from github.io or locally. Do not use node.js.
2. Data preservation is top priority. Use the browser's capabilities to ensure data is saved after each action. All the data should be exportable and importable via a json file. Keep an undo/redo stack. Allow experimentation, having "draft" timetables, such that one can open a new draft without erasing existing ones, moving convenietely between drafts via tabs.
3. The main GUI object is a timetable, separated according to configuration-provided times and days. The courses that should be scheduled in the table are given as rectangles, with the name of the course clearly visible inside. The rectangles should be draggable from a storage area to any slot in the timetable and back, snapping into the nearest timetable slot. Allow several rectangles in the same time slot, with visible que that there are some rectangles there and an easy way to browse through them by clicking.
4. The default days are: Sunday, Monday, Tuesday, Wednesday, Thursday. The default times are 8:30-9:30, 9:30-10:30, 10:30-11:30, 11:30-12:30, 12:30-13:30, 13:30-14:30, 14:30-15:30, 15:30-16:30, 16:30-17:30, 17:30-18:30.
5. We maintain a list of "required external courses": courses from another faculty that students in the same semester must also be able to attend. External meetings appear on every draft, but an overlap with one external meeting is not necessarily a constraint failure because courses can offer alternative groups.
6. External meetings have three types: lecture (`הרצאה`), tutorial (`תרגול`), and laboratory (`מעבדה`). A group may contain more than one meeting, and all meetings belonging to the selected group must be collision-free.
7. Lecture groups are the main groups. Tutorials are associated with a lecture by the first two digits of their section number after the alphabetic prefix. For example, tutorial `SE026` is associated with lecture `SE024` because both belong to family `02`.
8. A normal external course remains feasible when there is at least one lecture group, plus at least one associated tutorial group, for which every meeting is free of collisions with courses placed in the active draft. Laboratories are standalone alternatives: a laboratory course remains feasible when at least one complete laboratory group is collision-free. A warning is shown only when an external course has no valid combination left; individual overlaps may still be highlighted to explain which alternatives were eliminated.
9. External courses can be entered one meeting at a time or imported from CSV. The CSV contains no required header and uses these leading columns: course number, course name, section/group name, meeting type, Sunday time, Monday time, Tuesday time, Wednesday time, Thursday time. Additional trailing source-system columns are ignored. Each row contains one time range in exactly one weekday column. Repeated rows with the same course number, section code, and meeting type are meetings of the same group. Different group codes describe alternatives. Time ranges may span several timetable slots, such as `12:30-15:30`.
